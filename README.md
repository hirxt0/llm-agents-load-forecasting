# llm-agents-load-forecasting

Помогает ли контекст LLM-агенту прогнозировать электропотребление зданий, и окупается ли он? Сравниваем одиночного LLM-агента, мультиагентную систему и классические/foundation-модели на реальных зданиях BuildingsBench с учётом стоимости и проверкой на утечку данных.

Общие правила для всей команды: [`shared/DATA_GUIDE.md`](shared/DATA_GUIDE.md) (данные, период, метрики, формат результатов), ТЗ на бейзлайны: [`shared/BASELINE_TZ.md`](shared/BASELINE_TZ.md).

---

## Одиночный агент

GPT-5 сам пишет прогноз на 24 часа (24 числа + обоснование), инструменты дают ему только контекст. Цикл ReAct: агент вызывает инструменты, смотрит результат и сдаёт прогноз через `submit_forecast`.

**Лесенка контекста** - главная абляция: на каждой ступени агент получает больше информации.

| Вариант | Что видит агент |
|---|---|
| `no_tools` | Только последние 168 часов в сообщении (LLM без агентности, как LLMTime) |
| `series` | Анализ ряда, значения истории, готовые профили (вчера, неделю назад, среднее за 2 недели, типичные будни/выходные) |
| `calendar` | + праздники, обезличенные сведения о здании (тип, площадь, год, климат) |
| `weather` | + температура: история и прогноз на сутки с реалистичной ошибкой |
| `full` | + новости Википедии на момент прогноза и город здания |

**Данные:** 100 зданий × 4 окна (будний, выходной, праздник, погодная аномалия), основные эксперименты - на 200 окнах; 10 отдельных зданий для настройки. Подробности - в `DATA_GUIDE.md`.

## Защита от утечки данных

| Риск | Что сделано |
|---|---|
| Агент увидит будущее ряда | В среде агента есть только 336 часов истории |
| Новости из будущего | Момент прогноза задаёт среда; страницы Википедии берутся в версии за 1 час до начала прогноза (с переводом местного времени в UTC), id ревизии логируется |
| Фактическая погода на день прогноза | Вместо факта - прогноз с ошибкой (AR(1), 1 -> 2 °C, ночью и зимой больше), одинаковый для всех систем |
| Память LLM о зданиях и событиях | Здания обезличены, город только в `full`, запрет внешних знаний в промпте |
| Подгонка под тест | Промпт и параметры настраиваются на отдельных 10 зданиях |

Проверки остаточной утечки (дают нижнюю оценку, а не доказательство отсутствия):
- **скрытые даты** - тот же прогноз без настоящих дат и названий праздников, сравнение с тестом эквивалентности;
- **проба на запоминание** - узнаёт ли модель здание по настоящему названию из датасета;
- **аудит рассуждений** - годы и события в текстах агента, которых не было в ответах инструментов.

## Метрики и статистика

Основная метрика - **NRMSE** (CV(RMSE), как в BuildingsBench, нормировка по среднему истории); дополнительно NMAE, MASE, NMBE, MAE, RMSE; MAPE - только для коммерческих зданий. Результаты - отдельно по коммерческим и жилым зданиям и по типам дней. Сравнения: единица анализа - здание (кластерный бутстреп, Wilcoxon, поправка Холма). Плюс стоимость: токены, доллары, время, доля сбоев.

## Запуск

Окружение: Python 3.12, `pip install -r requirements.txt` (на Windows создавать venv по короткому пути, иначе не грузится `pyarrow`). Ключ - в файле `.env` по образцу `.env.example`; для ключа от сервиса-посредника нужен ещё `OPENAI_BASE_URL`. Данные: готовые окна лежат в `shared/`; для погоды и метаданных зданий нужны `data/raw/` (BuildingsBench `BDG-2`/`LCL`, `bdg2_metadata.csv`, погода Лондона в GMT с Open-Meteo).

Порядок работы (скрипты в `src/`, все параметры - `--help`):
1. `data.py` -> `export_windows.py` - пересобрать выборку и общие файлы (уже сделано).
2. `run_forecast_agent.py --dry-run` - проверка без API.
3. `run_forecast_agent.py --split dev` - настройка на отладочных зданиях.
4. `run_forecast_agent.py --split test --subset main --variant <ступень>` - лесенка; плюс `--masked-dates`, повтор `--subset repeat --repeat 1`.
5. `probe_memorization.py`, `audit_traces.py` - проверки утечки.
6. `summarize.py` - все метрики, сравнения, типы дней, стоимость для всех систем команды.

Прогон можно прерывать: при повторном запуске готовые окна пропускаются. Результаты - в `results/<конфигурация>/` (`predictions.csv`, `scores.csv`, полные диалоги агента в `trajectories.jsonl`).

## Структура

```
shared/                      общие для команды данные, инструкции, ТЗ
src/data.py                  отбор зданий и окон (гигиена, типы дней)
src/export_windows.py        выгрузка окон в shared/
src/context.py               контекст: здание, праздники, погода, новости «на дату»
src/forecast_env.py          среда агента: инструменты, лесенка, скрытые даты, промпт
src/agent.py                 цикл LLM-агента (OpenAI/GPT-5, совместимые шлюзы, Claude)
src/run_forecast_agent.py    прогон агента
src/probe_memorization.py    проба на запоминание
src/audit_traces.py          аудит рассуждений
src/metrics.py, src/stats.py метрики и статистика (общие для команды)
src/summarize.py             сводные таблицы для статьи
src/legacy_v1/               первая версия эксперимента (агент-«чистильщик»), не поддерживается
reports/                     исследование актуальности темы
```
