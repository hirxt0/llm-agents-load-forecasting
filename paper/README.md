Рабочее название — **«Сравнение одиночного LLM-агента, мультиагентной системы и моделей временных рядов в задаче суточного прогнозирования электропотребления зданий»**.

- [Рукопись](manuscript.md) содержит общий каркас, написанные фрагменты методов, таблицы завершённых экспериментов и задания участникам.

- [Результаты](../results/README.md) описывают сохранённые прогнозы, метрики и стоимость.

Имена авторов впишите в эту таблицу при распределении разделов. Редактор сводит текст после заполнения частей.

## Текущий срез

Основные пять конфигураций одиночного агента рассчитаны на 200 окнах каждая. Классические модели рассчитаны на 400 test-окнах, из которых в статье используются общие 200. Скрытие дат выполнено на 200 окнах. Четыре частичных по объёму серии повторов хранятся как дополнительные материалы; по решению команды основное сравнение использует один запуск каждой конфигурации.

Основная пара агентных систем использует `series` в §5.2 и §6.1. В §6.1 также сохранены результаты Chronos-Bolt, Chronos-2 и TimesFM 2.5 из редакции автора бейзлайнов.

В поставке мультиагентной части есть исходные коды и [метрики двух dev-пилотов](../multi_agent_forecasting/reports/dev_smoke_metrics.csv). При интеграции прошли восемь тестов и offline-прогон 40 dev-окон с программной политикой. Эти проверки подтверждают работу конвейера. Полных test-прогнозов мультиагентной системы в текущем срезе нет.

Аннотация готова для обсуждения текущей версии работы. После получения MA test-результатов обновите последнее предложение и добавьте главный итог сравнения трёх подходов. До этого вывод о победителе среди трёх подходов остаётся открытым.

## Правила заполнения

1. Маркеры `[ДОПОЛНИТЬ: ...]` обозначают конкретную работу автора. Перед подачей замените их проверенным текстом.
2. Для итогового сравнения используйте одинаковые окна и одну формулу NRMSE. При двух окнах на здание сначала берётся среднее внутри здания, затем медиана по зданиям.
3. Проверяйте столбец `n_windows`. В общей таблице должно быть по 100 окон каждого датасета на метод. Строки повторов содержат по 25 окон и относятся к другой выборке.
4. Имена `snaive_24` и `bl_snaive_24`, а также `snaive_168` и `bl_snaive_168` обозначают дубли эталонов в текущей сводке. В статье каждый эталон приводится один раз.
5. Таблица с «лучшей конфигурацией» по test описывает наблюдённые результаты. Выбор такой конфигурации по итоговой ошибке не считается независимой настройкой на dev.
6. Сравнение SA/MA включает различия числа вызовов модели. Если бюджеты не выровнены, описывайте результат как сравнение конкретных систем при их фактических бюджетах.
7. Стоимость из журналов рассчитана по тарифу. В MA тарифы заполняются в локальном окружении, в статье рядом с ценой указываются провайдер и дата тарифа.
8. Повторы и проба запоминания исключены из обязательного плана. Соответствующие заявления об устойчивости и отсутствии запоминания не входят в выводы.

## Сборка общей оценки

Мультиагентный модуль по умолчанию сохраняет прогнозы в общую папку `results/ma_*_test/`. После получения полного набора прогнозов выполните из корня репозитория:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
python -m one_agent_forecasting.src.summarize --split test --subset main
```

Для явного парного сравнения нужных папок можно использовать `multi_agent_forecasting/evaluate.py --runs ...` из каталога мультиагентного модуля. Текущая общая сводка автоматически формирует лестницу и сравнения агентов с бейзлайнами; отдельные SA/MA-пары следует задать при финальном анализе через этот оценщик и согласовать семейство гипотез.

Таблицы в рукописи являются зафиксированным срезом. При появлении новых прогнозов обновите их из CSV и повторно проверьте покрытие окон.
