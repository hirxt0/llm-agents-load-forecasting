# Agent Analyzer

Прогноз почасового электропотребления на следующие сутки. Данные: BDG-2 и LCL; история — 336 часов, горизонт — 24 часа. Модель — GPT-5, API — `https://apinet.cloud/v1`, уровень рассуждений — `low`.

Supervisor получает отчёты аналитика ряда и независимого проверяющего, затем формирует итоговый прогноз. Варианты `calendar`, `weather`, `full` добавляют анализ календаря, погоды и новостей. Диалоги и наборы инструментов агентов разделены.

## Размещение в общем репозитории

Модуль находится в `multi_agent_forecasting/`. Запускайте `main.py` и тесты из этой папки, чтобы локальные импорты разрешались корректно. По умолчанию конфигурация использует общие `../shared/` и `../results/`. Исходные данные ищутся в тех же расположениях `data/raw/`, что у одиночного агента. Путь к каталогу с подпапками BDG-2 и LCL можно переопределить через `RAW_DIR`, остальные пути — через `WINDOWS_DIR`, `CONTEXT_DIR` и `RESULTS_DIR`.

```powershell
cd multi_agent_forecasting
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python main.py --dry-run --split dev --output ../results/ma_integration_dry-run_dev
```

Для API-запусков создайте локальный `.env` из шаблона. Общие результаты сохраняются в папки `results/ma_*_test/`, поэтому их подхватывает сводка одиночного агента. Перед итоговым сравнением проверьте полное покрытие общих 200 окон. Приведённые ниже два API-пилота предоставлены автором модуля вместе с исходным CSV.

Завершены два API-прогона варианта `series`: по одному dev-окну BDG-2 и LCL. Каждый прогноз содержит 24 значения; оба запуска завершились без fallback. Это предварительная проверка на двух окнах, а не результат полного эксперимента.

Сводные метрики сохранены в [reports/dev_smoke_metrics.csv](reports/dev_smoke_metrics.csv). Файл входит в репозиторий.

## Исходные инструкции для отдельного каталога

Следующие инструкции описывают исходную автономную поставку. При работе внутри общего репозитория используйте размещение и автоматические пути из раздела выше.

### Запуск в PowerShell

Требуется Python 3.10 или новее. После распаковки или клонирования нужно выполнить `setup.ps1` и заполнить `OPENAI_API_KEY` в созданном `.env`. Файл `.env.example` содержит только шаблон настроек.

```powershell
cd "$HOME/Desktop/Agent_analyzer"
./setup.ps1
./run.ps1 --check-api
./run.ps1 --dry-run --split dev
./run.ps1 --split dev --dataset BDG-2 --limit 1
./run.ps1 --split dev --dataset LCL --limit 1
```

Если политика PowerShell блокирует скрипты, запускай Python напрямую:

```powershell
./.venv/Scripts/python.exe main.py --check-api
./.venv/Scripts/python.exe main.py --split dev --limit 2
```

Ключ хранится в `.env`; шаблон — `.env.example`. `.env` исключён из Git. `OPENAI_MODEL=gpt-5`, `REASONING_EFFORT=low`; параметры одинаковы для всех агентов. Запуск без аргументов показывает справку.

## Эксперимент

Окна эксперимента находятся в `shared/`, исходные CSV — в `BDG-2/` и `LCL/`. Используется фиксированная выборка: 40 dev-окон 10 зданий и 400 test-окон 100 других зданий. Для теста по умолчанию выбираются основные 200 окон. История и целевые значения всех 440 окон сверены с исходными CSV.

Датасеты, окна и файлы контекста не входят в архив исходного кода и исключены из Git. Перед прогнозированием или запуском тестов нужно скопировать `windows_dev.parquet` и `windows_test.parquet` версии 2 из общего набора эксперимента в `shared/`. Альтернативный путь к готовым окнам задаётся через `WINDOWS_DIR` в `.env`. Исходные папки `BDG-2/` и `LCL/` размещаются рядом с `main.py`; погодный контекст требуется только соответствующим вариантам.

```powershell
./run.ps1 --split dev --variant series
./run.ps1 --split test --variant series
./run.ps1 --split test --subset repeat --repeat 1
./run.ps1 --split test --masked-dates
```

Каждый реальный прогон расходует баланс API. `--limit` ограничивает число окон, `--max-steps` — вызовы Supervisor, `--worker-steps` — вызовы каждого специалиста. Последний вызов специалиста резервируется для отчёта. Система останавливается после первого сбоя и сохраняет прогноз «как вчера» с `failed=true`. Повтор команды продолжает с необработанных окон; `--retry-failed` повторяет также сбойные окна. Изменённые код, модель или параметры требуют нового `--repeat` либо `--output`, чтобы не смешивать результаты.

Для `calendar`, `weather`, `full` нужны те же файлы контекста, что у одиночного агента:

| Файл | Назначение |
|---|---|
| `data/context/bdg2_metadata.csv` | Метаданные коммерческих зданий |
| `data/context/weather_london_openmeteo.json` | Погода Лондона в GMT |

Путь к контексту задаёт `CONTEXT_DIR` в `.env`. Указанные файлы отсутствуют; при необходимости запуск останавливается до обращения к API. Станционная погода BDG-2 доступна. Для сопоставимости с одиночным агентом погодные CSV LCL не заменяют данные Open-Meteo. Вариант `full` использует исторические ревизии новостей Википедии.

## Метрики и результаты

Основная метрика — NRMSE: RMSE / среднее 336 часов истории × 100. Дополнительно: NMAE, NMBE, MASE, MAE, RMSE; MAPE — только для BDG-2. `metrics.py`, `tools/context.py` и `tools/environment.py` используют общие с одиночным агентом формулы и правила контекста. Агрегирование: среднее по окнам здания, затем медиана по зданиям, отдельно для каждого датасета.

Агентам и их инструментам передаётся только история своего окна. Правильные ответы хранятся отдельно и используются после завершения прогнозирования. Настоящие названия зданий скрыты; тип дня из разметки теста также не передаётся. Будущая погода формируется оригинальной функцией `weather(..., mode="noisy")` с тем же зерном.

В `results/ma_<конфигурация>_<split>/`:

- `predictions.csv` — `building_id,window_id,hour,y_true,y_pred`;
- `scores.csv` — метрики окна, токены, вызовы, время и сбои;
- `trajectories.jsonl` — диалоги, инструменты и отчёты специалистов;
- `summary_metrics.csv`, `summary_daytypes.csv` — сводки;
- `windows/*.json` — атомарные контрольные точки для восстановления;
- `run_config.json` — параметры и SHA-256 кода и окон без ключа.

`cost_usd` остаётся пустым, пока в `.env` не указаны тарифы apinet.cloud за миллион токенов: `PRICE_INPUT_PER_M`, `PRICE_CACHED_INPUT_PER_M`, `PRICE_OUTPUT_PER_M`. Это расчётная стоимость по заданным тарифам, не выписка из кабинета. Reasoning-токены входят в выходные и повторно не прибавляются. Offline-проверки помечаются `dry-run` и не считаются результатами LLM.

Сравнение с одиночным агентом или бейзлайнами:

```powershell
./.venv/Scripts/python.exe evaluate.py --split dev --runs results/ma_gpt-5-low_series_noisy_BDG-2_all_dev results/ma_gpt-5-low_series_noisy_LCL_all_dev --output results/comparison_dev
./.venv/Scripts/python.exe -m unittest discover -s tests -v
```

В `--runs` можно передать папки мультиагентной системы, одиночного агента и бейзлайнов с одинаковым форматом `predictions.csv`. Оценка пересчитывает метрики по общим окнам из `shared/`, проверяет фактические значения и добавляет опорные методы «как вчера» и «как неделю назад». Статистика: отношение NRMSE по зданиям, 95% кластерный бутстреп, Wilcoxon и поправка Холма. Статистическое сравнение требует минимум пяти общих зданий. CSV совместимы с общей сводкой эксперимента.
