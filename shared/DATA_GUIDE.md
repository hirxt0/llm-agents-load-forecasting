# Данные для эксперимента: инструкция для участников

Этот файл - для всех, кто запускает свою систему (одиночный агент, мультиагентная система, бейзлайны). Чтобы результаты можно было сравнить, **у всех должны быть одни и те же данные, одни и те же дни и одинаковый подсчёт метрик.**

---

## 1. Какие данные берём

**Источник:** бенчмарк BuildingsBench (NREL), реальные почасовые данные электропотребления, единицы - **кВт·ч за час**.

**50 зданий:**

| Группа | Датасет | Сколько | Где | Годы |
|---|---|---|---|---|
| Коммерческие | BDG-2 | 25 | США: Беркли (Калифорния), Темпе (Аризона), Орландо (Флорида), Вашингтон | 2016–2017 |
| Жилые | LCL (Low Carbon London) | 25 | Лондон, Великобритания | 2012–2013 |

Коммерческие - это офисы, учебные корпуса, общественные здания, магазины, склады, парковки и т.д. Тип здания записан в столбце `btype`. Жилые - отдельные квартиры и дома с одним умным счётчиком.

**Ничего скачивать не нужно.** Всё уже нарезано и лежит в этой папке:

| Файл | Что внутри |
|---|---|
| `windows_test.parquet` | Ряды для 400 тестовых окон (история + правильный ответ) |
| `windows_dev.parquet` | Ряды для 40 отладочных окон (другие 10 зданий) |
| `test_windows.csv` | Список тестовых окон с датами: удобно открыть в Excel |
| `dev_windows.csv` | То же для отладочных окон |

## 2. Что такое «окно»

Одно окно - это одна задача прогноза:

- **история:** 336 часов, то есть **14 суток** подряд;
- **прогноз:** следующие **24 часа**, с **00:00 до 23:00** одних суток;
- прогноз всегда начинается **в полночь** (как в реальном прогнозе на сутки вперёд);
- окна одного здания не пересекаются.

**Всего:** 50 зданий × 8 окон = **400 тестовых окон**.

## 3. На каком промежутке тестируем

| Группа | Первый день прогноза | Последний день прогноза |
|---|---|---|
| BDG-2 (коммерческие) | 18.01.2016 | 30.12.2017 |
| LCL (жилые) | 23.01.2012 | 30.12.2013 |

Окна разбросаны по всем месяцам и дням недели. Точные даты каждого окна - в `test_windows.csv`: столбцы `history_start`, `history_end`, `forecast_start`, `forecast_end`, `forecast_weekday`.

**Основная выборка - 200 окон из 400:** по 4 окна с каждого из 50 зданий (окна с номерами 0, 2, 4, 6). В `test_windows.csv` у них `in_main_200 = True`. **Все системы гоняем на этих же 200 окнах.**

Если нужен повтор для оценки разброса между запусками - берём 50 окон с `in_repeat_50 = True` (окно 0 каждого здания).

**Отладочная выборка (40 окон, 10 других зданий)** - только для настройки промптов и параметров. Тестовые окна для настройки **не используем**, иначе результат будет подогнан под тест.

## 4. Формат файлов parquet

Одна строка - один час одного окна.

| Столбец | Что это |
|---|---|
| `building_id` | Здание и год, например `Bear_assembly_Harry@2017` или `MAC000708@2013` |
| `dataset` | `BDG-2` или `LCL` |
| `btype` | Тип здания (`office`, `education`, ..., `residential`) |
| `window_id` | Номер окна у этого здания: 0–7 |
| `step` | Час относительно начала прогноза: **от −336 до −1 - история, от 0 до 23 - прогнозируемые сутки** |
| `timestamp` | Дата и время (местное время здания) |
| `y_clean` | **Потребление, кВт·ч. Его и прогнозируем, по нему и считаем ошибку** |
| `y_raw` | Тот же ряд с редкими необработанными выбросами из исходного датасета. **Не использовать** |

Как достать одно окно:

```python
import pandas as pd

w = pd.read_parquet("shared/windows_test.parquet")
main = pd.read_csv("shared/test_windows.csv").query("in_main_200")      # 200 основных окон

for _, row in main.iterrows():
    win = w[(w.building_id == row.building_id) & (w.window_id == row.window_id)].sort_values("step")
    history = win[win.step < 0][["timestamp", "y_clean"]]   # 336 часов — это видит система
    truth = win[win.step >= 0].y_clean.to_numpy()           # 24 часа — только для подсчёта ошибки
```

## 5. Что сделать с данными до запуска

**Уже сделано (повторять не нужно):**
- выбраны здания с качественными рядами: без пропусков, нулей меньше 1%, без залипаний счётчика дольше 12 часов; у жилых домов - полный год данных и среднее потребление не меньше 0,05 кВт·ч;
- взята очищенная версия рядов из BuildingsBench (`y_clean`);
- нарезаны окна по 14 + 1 суток.

**Правила для вашей системы:**
1. **Системе даём только историю** (`step < 0`). Значения `step >= 0` - правильный ответ, его нельзя показывать ни агенту, ни инструментам, ни использовать для подбора параметров.
2. **Не берём данные вне окна:** ни другие окна того же здания, ни другие даты. Каждое окно решается само по себе, только по своим 14 суткам.
3. **Ряд не чистим и не сглаживаем:** данные уже очищены.
4. **Если модели нужна нормализация** (масштабирование и т.п.), считаем её только по истории окна, а прогноз переводим обратно в кВт·ч.
5. **Прогноз сдаём в кВт·ч**: ровно 24 неотрицательных числа на часы 00–23.
6. **Названия зданий системе не показываем.** Вместо `Bear_assembly_Harry` - обезличенный код, иначе LLM может «вспомнить» здание из открытых данных. В коде агента это функция `anon_id` из `src/context.py`.

## 6. Если ваша система использует внешний контекст

Если агентам нужны погода, праздники или сведения о здании, **берите их так же, как в одиночном агенте**, иначе сравнение будет нечестным. Проще всего вызывать готовые функции из `src/context.py`:

| Контекст | Откуда и как | Функция |
|---|---|---|
| Сведения о здании | Метаданные BDG-2: тип, площадь, год постройки. Название и город скрыты | `building_info(building_id)` |
| Праздники | Библиотека `holidays`: США по штату здания, Великобритания - Англия | `holiday_name(building_id, day)` |
| Погода | История - фактическая температура. **На день прогноза - не факт, а «прогноз погоды»: факт + ошибка от 1 °C утром до 2 °C к концу суток**, с фиксированным случайным зерном, чтобы у всех была одна и та же ошибка | `weather(building_id, ts_hist, ts_future, mode="noisy", key=(building_id, str(origin)))` |
| Новости | Портал «Current events» Википедии **в версии страницы на момент до начала прогноза**. Даты после начала прогноза запрещены | `news(day, origin, query)` |

## 7. Как считать метрики и сдавать результаты

**Метрики (согласованы): MAPE (%), MAE (кВт·ч), RMSE (кВт·ч).** Все считают одной функцией:

```python
from metrics import forecast_metrics            # src/metrics.py
m = forecast_metrics(truth, prediction)          # -> {"MAE": ..., "RMSE": ..., "MAPE": ...}
```

**Правила:**
1. Метрика считается **по каждому окну (24 часа)**, затем усредняется по окнам.
2. **Отдельно для BDG-2 и LCL.** Офис потребляет ~56 кВт·ч в час, квартира ~0,2: общее среднее MAE по всем зданиям бессмысленно.
3. Для MAPE приводим **медиану и среднее**. У жилых домов 18% часов с потреблением меньше 0,05 кВт·ч, на них MAPE разлетается до сотен процентов.
4. Два метода сравниваем **парным тестом Уилкоксона** по MAPE на одних и тех же окнах.

**Формат сдачи прогнозов** - файл `predictions.csv`, одна строка на час:

```
building_id,window_id,hour,y_true,y_pred
Bear_assembly_Harry@2017,0,0,153.21,148.90
Bear_assembly_Harry@2017,0,1,150.02,147.35
...
```

Положите его в `results/fc_<название-вашей-системы>_test/predictions.csv` - тогда `src/summarize.py` автоматически добавит вашу систему в общую таблицу рядом с одиночным агентом и бейзлайнами.

Для сравнения стоимости сохраняйте ещё по каждому окну: токены (входные, выходные, в т.ч. reasoning), число вызовов LLM, время в секундах, удалось ли сдать прогноз.

**Ориентиры (бейзлайны на 400 тестовых окнах):**

| | MAPE, медиана | MAPE, среднее | MAE | RMSE |
|---|---|---|---|---|
| BDG-2, AutoML (лучший) | 8,7% | 13,1% | 5,00 | 6,43 |
| BDG-2, «как вчера» | 9,4% | 14,2% | 5,67 | 7,23 |
| LCL, AutoML (лучший) | 44,3% | 61,8% | 0,095 | 0,148 |
| LCL, «как вчера» | 52,9% | 74,2% | 0,111 | 0,172 |
